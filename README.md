# FT2 — Fast Tracker 2

AY-трекер для ZX Evolution с TS-Config, на ассемблере Z80 (sjasmplus).
Наследник Fast Tracker для ZX (Sand/MhM, Orion/DR).

Целевое железо — своя плата на RP2350B: AY плюс блок, который формирует громкость
выхода чипа (ЦАП) и даёт FX в духе Atari ST (PWM, SID, sync-buzzer) без дёргания
регистров AY из прерывания. Промежуточная цель — AYX-32.

Шпаргалка ниже — что уже решено и как устроено. Обновляется по команде.

---

## Сборка и запуск

- **F5 в VS Code** (или `build.bat` из корня):
  1. sjasmplus `srs/main.asm`;
  2. spgbld `srs/spg.ini` → `srs/ft2.spg`;
  3. robimg кладёт `ft2.spg` в образ `tools/unreal/wc.img`;
  4. запускается Unreal.
- `tools/` (эмуляторы, образ диска) и `pentevo/` (исходники Evo, Unreal, доки
  TS-Config) лежат только локально, в git не входят.
- **Эмуляторы:**
  - **Unreal:** `tools/unreal/Unreal.exe` — наша сборка (см. ниже), оригинал
    tslabs 2024-07-08 лежит как `Unreal_orig.exe`.
  - **Xpeccy:** мышь работает нормально, есть свои баги.
- Эталон — настоящий ZX Evolution.

## Свой Unreal

- Исходник в `unreal/` — tslabs/zx-evo, коммит `02d4daf` (ровно та версия, из
  которой собран оригинальный exe). Собирается набором VS 2019 **v142**:
  `MSBuild unreal\Unreal_2017.sln -p:Configuration="Release Unreal" -p:Platform=x64`.
- Наши правки:
  - X-офсет (GXOFFS) в текстовом режиме, как в ПЛИС;
  - мышь по курсору Windows (у нас DirectInput отдаёт абсолютную позицию, оригинал
    из-за этого «носился»), скорость — `MouseDiv` в `Unreal.ini` (больше — медленнее).
- `Unreal.ini`: `MouseDiv=2`, `video=triple` (картинка ×3), `CONTROL=SYM`
  (Ctrl = Symbol Shift).
- Тестовую сборку класть рядом с ini того же имени: Unreal читает `<имя exe>.ini`.
- Мышь в Unreal не идеальна (ускорение Windows). Точная — в Xpeccy и на железе.

## Память

- Окна: 0 — коре (страница #00, IM1 на #38, стек #3E00-#3FFF), 1 — тулза или
  плагин (org #4000), 2/3 — данные тулзы и экран.
- Страницы переключаются **только макросами** (SETPAGEn/RESTPAGEn, MAPPAGE): они
  ведут тени в `SV_PAGES`.
- Карта страниц — в шапке `srs/mem_defs.asm`. Основное:

| Страницы | Что |
|---|---|
| #00 | коре |
| #04 | просмотр паттерна |
| #06 | банк шрифтов + значки |
| #08-#0F | графика спрайтов |
| #10/#11 | текстовый экран / шрифт (шрифт = экран XOR 1) |
| #12/#13 | второй экран / шрифт |
| #14/#15 | FAT32-драйвер: код / работа |
| #16/#17 | треки 1 и 2 (открыто два сразу) |
| #18-#1F | тулзы и плагины |
| #20-#27 | буферы обмена / отмены |
| #28-#47 | буфер файла трека |
| #48-#4B | буфер откомпилированного трека (≤ 32К) |
| #4C-#BF | пул: паттерны, инструменты обоих треков |
| #C0-#FF | система — не трогаем |

- Системные адреса в коре: API #3C00, переменные `SV_*` #3D00, тема
  `THEME_ATTR` #3D80.

## Кадр

- **IM1 каждый кадр по порядку:** музыка → мышь → вывод активного редактора
  (`SV_FRAME_HOOK`). IM1 ничего не решает, только выполняет по переменным.
- **Основной цикл:** вся логика, ввод, состояние.
- **Весь интерфейс рисуется каждый кадр и обязан влезать в кадр** в худшем
  случае. Пропуск перерисовки и кеш готовых строк — нельзя.
- Основной код не держит DI дольше ~32 тактов: импульс кадрового INT длится
  32 такта, его можно потерять, и музыка дёрнется.
- **Замер времени:** клавиша T включает полосу времени — фон красится своим
  цветом на каждый шаг, высота полосы = время шага. INT при этом переносится
  на строку растра 32.

## Трек и паттерн

- **Лимиты:**
  - паттернов 64;
  - инструментов 32;
  - орнаментов 16;
  - FX 32;
  - позиций 256;
  - роу 64.
- Откомпилированный трек ≤ 32К.
- **Паттерн:** роу = старший байт адреса (#80+роу, до 64 роу = страница 16К),
  младший — смещение в полосе 256 байт. 0 в любом поле = пусто.
- **Чип** (8 байт заголовка + 3 канала по 16, всего 64), 1 или 2 чипа:
  - заголовок: период огибающей 2, огибающая-2 2, шум 1, резерв 3;
  - канал: нота 1 (1..96, 97+ — команды нот), сэмпл 1, огибающая 1, орнамент 1,
    громкость 1, резерв 1, команда 1 — 2 байта, команда 2 — 2 байта, резерв 6.
- **Команда** — просто 2 байта. Что они значат, решают плеер и компилятор.
  На экране 4 hex.
- *(SDK ещё на старом формате команд: 2 × 4 байта. Переход — следующим шагом.)*

## Просмотр паттерна — новая схема (обсуждена, ещё не в коде)

- **Паттерн = одна страница 16К.** Строка 256 байт на роу: данные (2 чипа × 56)
  + готовый текст этой роу с пробелами, в полную ширину = 254 байта. Правка клетки
  пишет данные и тут же перерисовывает текст этой роу.
- **Текст элемента:** закрытое — начало открытого.
  - канал: `C-4 A1FE 1234 5678`, закрыт 8, открыт 18;
  - Env: `0134 1F 0000 `, закрыт 7, открыт 13.
  
  Добавки 10 и 6 чётные, поэтому чётность колонок для DMA не зависит от раскладки.
- **Огибающая как нота:** нота и признак «неточно» кладутся в данные при вводе.
  Переключение режима переписывает текст Env во всех роу (~3 кадра).
- **Вывод в IM1, по проходам:**
  1. поля — DMA-«черепица»: кусок на элемент, округлён до слова, внахлёст, сразу
     на все строки куска паттерна (~24 DMA за кадр, ~15К тактов);
  2. разделители — отдельно поверх: `│`/`║` или пробелы (настройка), `►`, если у
     закрытого канала есть скрытые данные;
  3. атрибуты — DMA строк-шаблонов (база / активный паттерн / строка
     редактирования), только при смене состояния строки;
  4. номера роу (общая колонка 00..3F) и ордер.
- **Полотно по ордеру** во всех режимах. Плей паттерна склеивает его сам с собой,
  в первом проходе сверху пусто. Пустые строки — одна DMA из готовой таблицы.
- **Смена открытого канала** меняет только список черепиц.
- Индикатор отставания (играет / показано, в роу и кадрах, максимум) — в плане.
- **Нерешено:** 64 страницы на трек × 2 трека не влезают в пул (116 страниц).

## Просмотр паттерна — что сейчас в коде

- **Таблица роу:** основной цикл каждый кадр решает, что в какой экранной строке:
  страница и роу паттерна, или пусто. Считается из ордера и режима: стоп, плей
  паттерна, плей сонга. Паттерн может быть длиной 1, поэтому на экране может
  идти много паттернов подряд — сплошное полотно, как в Bitphase.
- **Вывод роу в IM1 на стеке:**
  - процедура сохраняет SP в свой `ld sp,nn` в конце;
  - SP = данные роу;
  - `pop` + таблицы символов на границе 256 → текстовая страница.
  
  Адрес процедуры текущего пресета кладётся в `call` один раз перед циклом.
- **Режимов вида нет:** паттерн сам ужимается вокруг открытого элемента — канала
  под курсором или Env чипа. У закрытого канала видны нота + инструмент; если
  есть скрытые команды, вместо `│` стоит `►`.
- **Ширины и суммы** — таблицы в шапке `srs/patview.asm`:
  - 6 каналов с открытым каналом — 88 из 90;
  - 3 канала, всё открыто — 78.
- **Вью на 3 и 6 каналов** — отдельные тулзы. При переключении всё стопается.
- **Ордер:** `│r05│`, текущая позиция — `►r05│`. r — позиция повтора.

## Цвета и шрифт

- Цвет берётся **готовым из темы** — роль `CLR_*` → полный атрибут
  (paper<<4 | ink). Никаких расчётов и масок. Кривая тема — проблема темы.
- **Стиль Bitphase:**
  - рамки и разделители еле видны;
  - ярко только данные;
  - пустые значения — точки;
  - активный паттерн ярко, соседние тусклее (план).
- **Шрифты:** банк в странице #06, `Set_Font` + `Apply_UI_Glyphs` (значки поверх
  кодов #00-#1F).
- **Кнопки:**
  - малые 7×7 в одно знакоместо, нажатая — тот же код +1, сдвинута вниз-вправо;
  - большие — два знакоместа.
