# FT2 — архитектура интерфейса (ввод, поля, окна)

Черновик для согласования. Принципы — те же, что у вывода паттерна:
- IM1 ничего не решает: только **собирает ввод** (клавиатура, мышь) и **рисует** по готовым
  данным. Вся логика — в основном цикле.
- Никаких универсальных монстров: где проще процедурой — процедура. Таблицы — где они
  реально убирают ветвления.
- Цвета — готовые роли темы. Всё, что рисуется, укладывается в кадр.

---

## 1. Ввод

### 1.1. Клавиатура PC (PS/2)

**Источник** — лог сканкодов AVR (расширение Gluk-часов `#02`, см. `pentevo/docs/GluExt`):

```
OUT #DFF7,#F0 : OUT #BFF7,#02     ; включить лог (один раз)
OUT #DFF7,#F0 : IN  A,(#BFF7)     ; очередной байт: 0 - пусто, #FF - переполнение
```

Коды PS/2 набора 2: нажатие — `код`, отпускание — `F0 код`, расширенные — `E0 …`.
Unreal это эмулирует.

**IM1, каждый кадр** (коре, сразу после мыши): вычитываем лог до пустого и разбираем:
- **Карта нажатых** `KEY_DOWN` — 256 бит (32 байта): индекс = код, для `E0`-кодов +128.
  Отвечает на вопрос «держат ли клавишу сейчас» (выделение, Shift и т.п.).
- **Очередь событий** `KEY_QUEUE` — кольцо на 16 записей по 2 байта:
  `[код 0..255] [флаги: модификаторы Shift/Ctrl/Alt + PRESS/REPEAT]`.
  Отвечает на «что нажали» — для команд, ввода текста и нот.

**Автоповтор** — как на PC, только для последней нажатой клавиши:
- нажатие → событие `PRESS`;
- держат `KB_DELAY` кадров → `REPEAT`, дальше каждые `KB_RATE` кадров;
- отпустили или нажали другую → повтор прекращается.

`KB_DELAY`, `KB_RATE` — системные переменные (настройка трекера, по умолчанию 20 и 3).
Модификаторы (Shift, Ctrl, Alt) повтор не дают и событий сами не порождают — только флаги.

**Дребезга у PS/2 нет** (его снимает контроллер клавиатуры). Клавиатура Спектрума
(`#FE`) остаётся для совместимости: опрос матрицы в IM1, считаем нажатой после 2 кадров
подряд, те же события с кодами-заменителями.

**Чтение из кода:**
```
Key_Get       ; A - код, C - флаги; Z - очередь пуста
Key_Down      ; in: A - код. NZ - держат
```

### 1.2. Мышь — кнопки

Состояние каждой кнопки (левая, правая, средняя) ведёт IM1, по кадрам:

| Флаг | Смысл | Где нужно |
|---|---|---|
| `DOWN` | держат сейчас | выделение протяжкой, drag |
| `PRESS` | нажали в этом кадре | клик по кнопке, установка курсора |
| `RELEASE` | отпустили в этом кадре | завершение drag, «кнопка сработала по отпусканию» |
| `REPEAT` | как у клавиш: после `MS_DELAY`, потом каждые `MS_RATE` | стрелки скроллбара, перемотка |
| `DOUBLE` | второй `PRESS` за `MS_DBL` кадров в той же клетке | открыть, выделить слово |

То есть **«просто нажатое»** — это `DOWN`/`PRESS`, а **«с задержкой, как кнопки»** —
`PRESS` + `REPEAT`. Каждый обработчик сам выбирает, на что реагировать.
Колесо — счётчик с накоплением, как сейчас (`Mouse_Get_Wheel`).

### 1.3. Состояние плеера и контексты горячих клавиш

**Системные переменные плеера** (пишет плеер в IM1, читают все):
`SV_PLAY_STATE` (стоп / сонг / паттерн), `SV_PLAY_POS`, `SV_PLAY_ROW`, `SV_PLAY_SONG`.

**Контексты** — стек: `глобальный → редактор (паттерн / инструмент / …) → окно → поле в фокусе`.
Событие клавиатуры идёт **сверху вниз**, пока кто-то его не съест:
1. поле в фокусе (поле ввода съедает цифры и буквы, курсорные стрелки и т.п.);
2. открытое окно (Esc — закрыть);
3. таблица горячих клавиш текущего редактора;
4. глобальная таблица (F5 — плей сонга, F8 — стоп, переключение редакторов…).

**Таблица горячих клавиш** — в странице своего редактора:
```
db код, модификаторы, условие ; dw обработчик   ; конец - 0
```
`условие` — маска по состоянию: «только в стопе», «только при плее» и т.п. (0 — всегда).
Таблицы потом можно грузить из конфига — это и есть настраиваемые бинды.

## 2. Поля и события

**Поле** — прямоугольник экрана в знакоместах + кто его обрабатывает:
```
+0 x, +1 y, +2 w, +3 h        ; знакоместа
+4 флаги                      ; есть дети / курсор мыши (стрелка, I-образный, рука) / ...
+5 страница обработчика       ; 0 - коре
+6 адрес обработчика (2)
+8 дети (2)                   ; адрес списка дочерних полей, 0 - нет
+10 параметр (2)              ; что угодно для обработчика (номер канала, указатель...)
```
Список полей — подряд, конец — байт `#FF`.

**Поиск** (основной цикл, по координатам мыши в знакоместах — они уже готовы в
`SV_MOUSE_COL/ROW`): идём по списку верхнего уровня, первое совпадение → если есть дети,
спускаемся в них → самое глубокое совпадение получает событие. Глубина обычно 2: экран →
панель (ордер, паттерн, тулбар, окно) → кнопка.

**Внутри сложной панели детей не держим, а считаем процедурой.** Пример — паттерн: панель
одна, её обработчик сам переводит колонку мыши в «элемент + поле» по таблицам раскладки
(`Item_Col`/`Item_W` уже есть). Так не надо перестраивать дерево при смене раскладки.

**События** (код в A, параметры в регистрах):
`HOVER_IN`, `HOVER_OUT`, `PRESS`, `RELEASE`, `CLICK`, `DOUBLE`, `REPEAT`, `DRAG`,
`RCLICK` (правая), `WHEEL`, `KEY`, `FOCUS_IN`, `FOCUS_OUT`.

**Вызов обработчика:** обработчики живут в странице своего редактора / плагина, в окне 1
(`#4000`), как сейчас тулзы. Коре делает дальний вызов: `SETPAGE1 стр / call адр /
RESTPAGE1`. Окно 2 (`#8000`) и 3 — под данные (паттерны, экран).
*(Ты предлагал `#8000` под обработчики — тогда данные редактора уезжают в окно 3 вместе
с экраном. Нужно решить, см. вопросы.)*

## 3. Фокус, наведение, курсор

Глобально помним два поля: **`HOVER`** (под мышью) и **`FOCUS`** (куда идёт клавиатура).
- При смене — старому `*_OUT`, новому `*_IN`. Каждый обработчик сам решает, как
  показать: рамка ярче (ордер, паттерн), подсветка кнопки, курсор-рамочка на цифре.
- Подсветка — это **атрибуты готовыми цветами** (роль «рамка в фокусе» и т.п.), рисуется
  поверх обычных. У паттерна — проходом атрибутов в IM1 (как строка редактирования).
- **Форма курсора мыши** — из флагов поля под мышью (стрелка / ввод текста / рука);
  меняем номер тайла спрайта, это бесплатно.

## 4. Кнопки

- **Малая кнопка** — 2 знакоместа, рамка 15×7 (уже в шрифте: `[+]`, `[−]`, нажатые —
  код+`#10`).
- **Кнопка с текстом** — `[ Play ]`: края — значки рамки, середина — текст; нажатая —
  другой набор значков краёв + сдвиг цвета (готовая роль «кнопка нажата»).
- Кнопка = поле. Нажатый вид — пока `DOWN` и мышь над ней; срабатывает по `RELEASE` над ней
  (как в Windows: увёл мышь — отмена). Для кнопок «держать — повторять» (перемотка) —
  по `PRESS` + `REPEAT`.

---

## 5. Скроллбар

Структура в памяти вызывающего:
```
+0 x, +1 y, +2 длина (знакоместа), +3 флаги (гориз/верт)
+4 всего (2), +6 видно (2), +8 позиция (2)
```
- `SB_Draw (IX)` — рисует: стрелки, дорожка, ползунок (длина ~ видно/всего, минимум 1).
- `SB_Mouse (IX)` — по событию мыши: стрелки (`PRESS`/`REPEAT` → ±1), дорожка (страница),
  ползунок (`DRAG` → позиция пропорционально). Возвращает новую позицию и флаг «изменилась».
- Один код на всех: ордер, паттерн, списки файлов, окна.

## 6. Поля ввода

Тип поля определяет, какие символы допустимы и как они превращаются в значение:

| Тип | Пример | Значение |
|---|---|---|
| `HEX1` | `F` | 4 бита |
| `HEX2` | `1F` | байт |
| `HEX4` | `0134` | слово |
| `SYM32` | `A` | 1..32 (инструмент: 1..9, A..W) |
| `NOTE` | `C-4` | нота с пианино-клавиатуры (Z S X D C…, октава из настройки) |
| `DEC` | `125` | число десятичное |
| `TEXT` | `Song name` | строка N знаков |

- Клик → фокус + курсор на нужный знак; ввод пишет знак и двигает курсор; Enter/Tab —
  следующее поле; Esc — вернуть старое значение.
- Значение — по указателю (страница + адрес), запись — через процедуру типа (для паттерна —
  ещё и перерисовка текста роу, `Row_To_Text`).
- Та же машинка — и для клеток паттерна, и для полей в окнах.

## 7. Окна

```
+0 x, +1 y, +2 w, +3 h, +4 стиль рамки, +5 роль цвета фона, +6 заголовок (2),
+8 поля (2), +10 обработчик (страница + адрес)
```
- **Открытие:** то, что под окном (символы + атрибуты), сохраняем DMA в буферную страницу;
  рисуем рамку, фон, заголовок, кнопки (`[x]` закрыть).
- **Закрытие:** возвращаем сохранённое DMA.
- **Стек окон** (модальные — верхнее забирает весь ввод). Вывод паттерна под окном
  продолжает идти, но окно перерисовывается после него в том же кадре.

## 8. Контекстное меню (правая кнопка)

Окно-список: пункт = текст + подсказка клавиши + действие + доступен ли.
- `RCLICK` на поле → его обработчик возвращает меню для этого места (канал, ордер…).
- Меню — у мыши (прижато к краям экрана), пункт под мышью подсвечен, клик → действие →
  закрыть; клик мимо или Esc → закрыть.
- Для паттерна: копировать / вырезать / вставить / вставить смешиванием, транспонировать
  ±1 / ±12, очистить, интерполировать, растянуть / сжать, заглушить канал, соло.

## 9. Документация (форматы, плееры, трекеры)

Разбор присланных материалов в готовые доки — отдельным заходом, в `doc/`:
- `doc/ay.md` — регистры AY / YM / AY8930 и порты;
- `doc/formats/*.md` — форматы модулей (PT1/2/3, FTC, ASC, …) в виде «бери и пиши

  команды), возможности, горячие клавиши.

## 10. Плей / стоп

Есть: 1 — плей сонга, 2 — плей паттерна, 3 — стоп, 4 — продолжить, длинный тестовый ордер.
Дальше — кнопки на экране (п.4) и бинды на F5…F8 (п.1).

## Порядок работ

1. Ввод в коре: лог PS/2, карта и очередь клавиш, автоповтор, состояния кнопок мыши.
2. Поля и маршрутизация событий, фокус/наведение.
3. Кнопки (с текстом), скроллбар.
4. Поля ввода → редактирование клеток паттерна.
5. Окна → контекстное меню.
6. Доки по форматам и трекерам.

   `Q 2 W 3 E R 5 T 6 Y 7 U`)?
