# Порты AY: кто что занимает (справка для ZX Trinity)

Задача: найти, где у AY есть свободное место для регистров Trinity, чтобы не
мешать другим картам и чипам и не ломать им звук.

Источники (смотрено по коду, не по памяти):
- Unreal (`unreal/Unreal/io.cpp` ~780–860, ~1375–1395; `sound/ayx32.h`) — как эмулятор
  декодирует TurboSound, TS-FM, AYX-32, SAA, Quadro;
- ZX-MultiSound (`schemes/zx-multisound-master/cpld/rtl/top.v` ~102–145, 361–366) — живое железо
  TurboSound FM + SAA;
- ZX Evo TS-Config (`pentevo/fpga/current/z80/zports.v` ~632–635) — встроенный AY Evo;
- `doc/ay.md`, `docs/ay_ports.txt` — сам AY.

## 1. Порты

| Порт | Что |
|---|---|
| `#FFFD` запись | выбор регистра AY (адресная защёлка) — и **управление картами** (см. ниже) |
| `#FFFD` чтение | значение выбранного регистра |
| `#BFFD` запись | запись в выбранный регистр |

Декодирование неполное: обычно `A15`, `A14`, `A1 = 0` (Evo: младший байт `#FD` и `A15`).
MultiSound для `#FFFD` смотрит ещё `A13` (`#DFFD` у некоторых машин — память).

## 2. Значения, которые пишут в `#FFFD`, — кто что занял

| Значения | Кто | Что делает |
|---|---|---|
| `#00`–`#0F` | сам AY / YM2149 | регистры R0–R15 (R14, R15 — порты IOA / IOB: на 128К RS232 / MIDI / клавиатура, «AY-мышь» в эмуляторах — **не трогать**) |
| `#10`–`#12` | AYX-32 | расширение PSG (TDC каналов A, B, C) |
| `#19`–`#1E` | AYX-32 | громкости каналов отдельно на L / R |
| `#40`–`#46` | AYX-32 | DAC: управление, громкость L / R, частота, FIFO, данные |
| `#D0`–`#D6` | AYX-32 | выбор PSG, управление каналами, master L / R, таблица амплитуд |
| `#E0`–`#EF` | AYX-32 | сигнатура (`#AA55`), команды, статус, ошибки, версия, частота ядра |
| `#F0`–`#FF` | TurboSound / TS-FM / MultiSound | **управление картами**, это не номера регистров |

Как разбирают `#F0`–`#FF`:
- **TurboSound (NedoPC), TS-FM** — `(val & #F8) == #F8`: бит 0 — выбор чипа (`#FF` — чип 0,
  `#FE` — чип 1), для YM2203 бит 1 — чтение статуса FM вместо регистра, бит 2 — FM выкл.
- **MultiSound** — шире, весь `#F0`–`#FF` (`d[7:4] == 1111`): бит 0 — чип, бит 1 — статус,
  бит 2 — FM выкл, **бит 3 = 0 — включить SAA1099** (`#F7`), 1 — выключить.
- **AYX-32** — тоже `#F8`–`#FF`, выбор чипа (в Unreal: `~val & 1`).
- **Quadro** (в Unreal) — выбор чипа не значением, а адресом порта (бит A12).

## 3. Что делает настоящий AY с номерами `#10` и выше

У AY-3-8910 старшие биты номера регистра (DA7–DA4) — маска выбора чипа, у обычных
чипов `0000`. Записал в `#FFFD` номер `#10` и выше — **чип «отключается»** и игнорирует запись
и чтение, пока снова не выберут регистр `#00`–`#0F`. На этом стоят и TurboSound (`#FE`/`#FF`),
и AYX-32 (свои регистры от `#10`). YM2149 ведёт себя так же.

Значит, номера `#10`–`#EF` безопасны для живых AY и для их звука.

## 4. Конфликт на шине: встроенный AY машины

- MultiSound при обращении к `#FFFD` / `#BFFD` держит **IORQGE** — это отключает встроенный AY
  машины (на Evo — её YM2149), отвечает только карта.
- Evo: встроенный AY декодирует `#FD` + `A15` (BDIR / BC1 — `zports.v`).
- **AY-мышь, AY-принтер, RS232 / MIDI / клавиатура 128К** — на R14 / R15 (порты IOA / IOB), ножки
  **встроенного** AY машины (Unreal: AY-мышь — чтение R14, `io.cpp` ~854, ~1381). Отключил
  встроенный AY целиком через IORQGE — отключил и их.
- Trinity с живыми AY на борту должна делать так же (IORQGE), иначе на Evo две пары AY ответят
  разом. И должна уметь это отключать (джампер / настройка), если её AY не нужны.
- **Поэтому IORQGE — по номеру регистра**: выбран R0–R13 или блок Trinity — отвечает карта;
  выбран **R14 / R15** — карта молчит, отвечает встроенный AY (мышь, принтер работают как раньше).
  Запись номера (`OUT (#FFFD)`) видят оба AY — безвредно. Последний номер держит защёлка логикой
  (IORQGE нужен быстро, в цикле IORQ), RP только снифает. Запасной вариант — вывести IOA / IOB наших
  AY на гребёнку. На Evo мышь PS/2 и порты встроенного YM2149, похоже, не выведены — но карта для всех.

## 5. Выводы — где поле для Trinity

1. **`#00`–`#0F`** — сам AY, наше не кладём.
2. **`#F0`–`#FF`** — управление картами. Не трогаем, но **выбор чипа понимаем как все**:
   `(val & #F8) == #F8`, бит 0 — чип (TurboSound-совместимость для наших двух AY). Биты 1, 2, 3
   (статус FM, FM, SAA) — чужие, игнорируем.
3. **AYX-32 занимает** `#10`–`#12`, `#19`–`#1E`, `#40`–`#46`, `#D0`–`#D6`, `#E0`–`#EF`. AYX-32 —
   замена чипа AY в DIP-40, его могут поставить **прямо в наши панельки** — тогда он увидит наши
   записи. Поэтому наши номера с его номерами не пересекаем.
4. **Свободно**: `#13`–`#18`, `#1F`–`#3F`, `#47`–`#CF`, `#D7`–`#DF`. Самый широкий кусок —
   **`#47`–`#CF`**.
5. **Предложение (на утверждение автора)**: блок Trinity — **`#A0`–`#BF`** (32 регистра на
   выбранный чип), в середине свободного куска, подальше от занятых AYX-32 областей.
   - запись: `OUT (#FFFD),#Ax` -> `OUT (#BFFD),значение` — как обычный регистр AY, плееру и
     трекеру ничего нового;
   - чтение: `OUT (#FFFD),#Ax` -> `IN #FFFD` — живой AY в это время отключён (п.3), отвечает RP-AY;
   - регистры у каждого чипа свои (чип выбран `#FE` / `#FF`) — по 3 канала на чип;
   - **сигнатура** в первом регистре (например `#A0` -> читается «TR» или версия): так софт
     узнаёт, что Trinity есть, и не пишет эффекты вслепую.
6. Отдельный порт под Trinity не нужен: всё через порты AY, как у AYX-32.

Что положить в регистры (уровни каналов, эффекты SID / тремоло / цифродрамы, синхронизация) —
решаем вместе с трекером FT2 (`doc/zx-trinity.md`, «Открыто», п.1).

## 6. Проверить ещё (не нашёл в наших источниках)

- Документацию AYX-32 от автора: не зарезервированы ли у него номера сверх перечисленных
  (вдруг весь `#10`–`#EF` объявлен «под расширение»).
- Другие карты на портах AY: ZXM-SoundCard (micklab), карты с SAA на `#FF` / `#1FF`,
  «AY-мышь» на R14 — подтвердить, что `#A0`–`#BF` у них не заняты.
