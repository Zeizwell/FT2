# Paula: как она звучит и как получить такой же звук (или лучше) в ZX Trinity

Разбор материалов пользователя из `Paula/` (в git не добавлены): Verilog Paula (`paula.v`,
`amiga_replacement_project/paula/Paula.v`, `Better_Audio.v`), эмуляция pt2-clone (`pt2_paula.c`,
`pt2_blep.c`, `pt2_rcfilters.c`), WinUAE (`audio.cpp`), MilkyTracker (`ResamplerAmiga.h`), pocketmod,
PicoGUS (GUS / SB на RP2040), заметка о ресемплинге Amiga (`milkytracker.txt`), заметка о ЦАП (`ДАКИ.txt`).
Решения по карте в целом — `doc/zx-trinity.md` (п.5, GS-часть); здесь — только звук Paula.

## 1. Что такое Paula (звуковая часть)

| | Как устроено (по Verilog и Hardware Reference Manual) |
|---|---|
| Каналы | 4, у каждого своё DMA: сэмпл 8 бит со знаком, длина в словах (`AUDxLEN`), адрес (`AUDxLC`) |
| Частота канала | **своя у каждого**: период `AUDxPER` в тактах CCK (PAL 3 546 895 Гц). Ниже ~124 DMA не успевает (pt2-clone ограничивает 113), 0 = 65536 |
| Когда что берётся | новый период — только на границе сэмпла (refetch); громкость — тоже на смене сэмпла; DMA берёт слово = 2 сэмпла |
| Громкость | 0..64 (бит 6 = 64, всегда включено). **Не умножение, а ШИМ**: счётчик 6 бит на CCK, выход канала открыт `vol` тактов из 64 (≈ 55.4 кГц несущая) |
| Сведение | жёсткое стерео: каналы 0 и 3 — левый, 1 и 2 — правый |
| Модуляция | attach: канал пишет период и / или громкость соседнему вместо своего звука (редко, но бывает) |
| Выход | 8-битные ЦАП (в чипе — ШИМ / сигма-дельта по моделям), дальше **аналоговые фильтры на плате** |

### Фильтры на плате (номиналы — pt2-clone, сверено со схемами)

| Модель | Фильтр | Элементы | Срез |
|---|---|---|---|
| A500 rev 6A | постоянный ФНЧ 1-го порядка (6 дБ/окт) | R 360 Ом, C 0.1 мкФ | **~4421 Гц** |
| A500 / A1200 | «LED»: ФНЧ Саллен-Ки 2-го порядка (12 дБ/окт), включается битом CIA-A (`#BFE001` бит 1, яркость LED) | R 10к + 10к, C 6800 + 3900 пФ | **~3091 Гц**, Q 0.66 |
| A500 | ФВЧ 1-го порядка (развязка) | 1390 Ом, 22.33 мкФ | ~5 Гц |
| A1200 rev 1D4 | постоянный ФНЧ | 680 Ом, 6800 пФ | ~34 кГц (не слышно) |
| A1200 | ФВЧ | 1360 Ом, 22 мкФ | ~5 Гц |

## 2. Откуда «сочность»

1. **Нулевой порядок (ступеньки) на своей частоте у каждого канала.** Paula не интерполирует: держит сэмпл
   `период` тактов и меняет. Образы спектра (алиасинг) идут вверх, их частично срезает RC-фильтр. Получается
   «яркий», «стеклянный» звук — это и есть характер Amiga. Линейная / сплайн / sinc-интерполяция в
   плеерах на ПК звучит **не как Amiga** — тусклее.
2. **Нет общей частоты пересчёта.** У GS программа Z80 пересчитывает все каналы к одной частоте ЦАП —
   отсюда шипение и «грязь» на высоких нотах. У Paula каждая нота — свои честные ступеньки.
3. **8 бит + ШИМ-громкость.** Громкость не огрубляет сэмпл (нет квантования `сэмпл × громкость`),
   несущая ~55 кГц уходит фильтром.
4. **Фильтры A500**: 4.4 кГц срезают верх мягко (6 дБ/окт) — «тёплая» Amiga 500; LED делает «глухо»
   (им пользуются как эффектом, команда `E0x` в ProTracker). A1200 — без постоянного ФНЧ, звук ярче.
5. **Жёсткое стерео** (L = 0 + 3, R = 1 + 2) — узнаваемая «ширина» модулей.

## 3. Как получить тот же звук программно (эталон — pt2-clone, WinUAE, MilkyTracker «Amiga»)

Все три сходятся на одном методе (заметка `milkytracker.txt`, автор метода — Antti S. Lankila, WinUAE):

1. **Paula считаем абстрактно на её частоте (3.55 МГц), но не по тактам**, а по событиям: у канала фаза
   `+= CCK / (Fвых × период)` на каждый выходной отсчёт; перешла через 1 — следующий сэмпл.
2. **Каждая смена уровня — не острая ступенька, а BLEP** (ступенька с ограниченной полосой): к выходу
   добавляется заранее посчитанная «хвостовая» поправка. В pt2-clone: minBLEP, 16 переходов через ноль ×
   16-кратная передискретизация → **16 отсчётов поправки на каждый фронт**. Таблица одна, от частоты
   вывода не зависит. Так получаются честные ступеньки Paula **без лишнего алиасинга от пересчёта** в
   44.1 / 48 кГц.
3. **Громкость** — умножением на смене сэмпла (`сэмпл × vol / 64`). ШИМ не эмулируют: он даёт только
   несущую 55 кГц, которую всё равно срезал бы фильтр (на A1200 её не слышно).
4. **Фильтры — цифровые модели тех же RC**: ФНЧ 1-го порядка (A500), Саллен-Ки 2-го порядка (LED,
   переключается на лету), ФВЧ ~5 Гц. На стерео-шине после сведения — по 2 канала.
5. **Ограничение метода**: частота вывода ≥ 31 389 Гц (`CCK / 113`); у нас 44.1 / 48 кГц — годится.

Варианты точности (все — режим «Paula» в `doc/zx-trinity.md`):
- **Paula A500** — BLEP + ФНЧ 4.4 кГц + LED по команде + ФВЧ;
- **Paula A1200** — BLEP + LED по команде + ФВЧ (без 4.4 кГц) — ярче;
- **WinUAE-вариант** — sinc-очередь вместо minBLEP (то же по смыслу, дороже) — не нужен.

## 4. Хватит ли RP2350 (оценка нагрузки)

| Что | Цена на один выходной отсчёт |
|---|---|
| канал: фаза, проверка смены сэмпла, выборка | ~10–15 тактов |
| BLEP: активная поправка — до 16 умножений-сложений, только пока идёт «хвост» фронта | 0..~35 тактов |
| фильтры (на L и R): 1 + 2 + 1 полюса | ~20 тактов на отсчёт стерео |

- **4 канала, 48 кГц, худший случай** (каждый отсчёт — фронт): 4 × 48 000 × ~50 ≈ **10 млн тактов/с ≈
  7 % одного ядра 150 МГц**. 8 каналов — ~14 %, 32 канала — ~50 %.
- У Cortex-M33 есть FPU (одинарная точность) и DSP-команды (`SMLAD` — два 16-битных MAC за такт): можно
  `float`, как pt2-clone, или фиксированная точка Q15 — ещё вдвое дешевле.
- Подтверждение из практики: **PicoGUS** на RP2040 (без FPU!) эмулирует GUS — 32 голоса, 44.1 кГц,
  сэмплы в PSRAM. RP2350 сильнее; 4–8 каналов Paula для неё — мелочь.
- **Сэмплы в PSRAM** (8 МБ, QSPI через XIP-кэш 16 КБ): канал читает подряд, 1 байт на сэмпл — кэш
  справляется. Короткие часто играемые сэмплы при желании — копией в SRAM (520 КБ).
- Остаток ядра — на команды GS, MP3 / OGG, эффекты. Второе ядро RP-GS — шина GS и PSRAM.

**Вывод: внешний DSP не нужен.** Всё, что делает звук Paula, считается программно с большим запасом.

**OPL4 на той же RP-GS** (решено ранее, `doc/trinity-concept.md`): эмуляция YMF278B (ymfm, BSD) — тяжёлая, по
PicoVerse 2350 впритык (для плотной полифонии они собирают 22 кГц). Поэтому **GS и OPL4 — режимы, а не вместе**
(переключение настройкой). Цифры выше — для режима GS / Paula; ymfm замерим тем же счётчиком `DWT_CYCCNT`.

## 5. Что делаем на лету программно

- переключение режимов **Classic / Paula A500 / Paula A1200 / HiFi** без остановки звука;
- LED-фильтр вкл / выкл (команда модуля `E0x` или настройка);
- период, громкость, панорама каждого канала; attach-модуляция;
- 8+ каналов, 16-битные сэмплы, панорама на канал (сверх Paula);
- плавная громкость без щелчков (рампа 1–2 мс) — в HiFi;
- реверберация / хорус — лёгкие (на запасе ядра), как опция;
- MP3 / OGG — программно.

## 6. Что выносить во внешнее (и стоит ли)

| Кандидат | Что даёт | Решение |
|---|---|---|
| **PCM5102A** (I2S, ~2 $, ~112 дБ) | чистый ЦАП, 3 провода, тактирование от BCK | **берём** (уже решено, модуль куплен) |
| PCM5122 (то же + I2C: громкость, фильтры) | аппаратная громкость без потери разрядности | не нужно: громкость в 32-битном микшере разрядность не теряет |
| ES9023 / ES9038 | «мягче» / дороже | не нужно |
| Аналоговые RC + LED на ОУ после ЦАП | «настоящая» A500 | **нет**: цифровая модель по тем же номиналам точнее (нет разброса деталей), переключается на лету и не трогает другие режимы; аналоговый фильтр резал бы всё (GS, HiFi, MP3) |
| «Железная» Paula: 4 × R-2R ЦАП, свой темп каждого (PIO + DMA) | честные ступеньки в аналоге | **нет** (решено ранее): дороже, шум питания R-2R, а BLEP даёт тот же звук |
| Дешёвый DSP (ADAU1701 / ADAU1401 SigmaDSP, ~5–10 $) | ревёрб / эквалайзер в железе | **нет**: нагрузка RP — единицы процентов; SigmaDSP программируется закрытой SigmaStudio, ещё одна прошивка и I2C |
| Отдельный аудио-чип звуковой карты (CS4231, ESS и т.п.) | — | **нет**: старое, дорогое, хуже PCM5102A |
| Вторая RP под звук | — | уже есть: RP-GS занята только GS (шина + микшер), RP-AY — отдельно |

## 7. «Лучше Paula» — режим HiFi

- полифазная sinc-интерполяция (8–16 отводов) или кубическая — без образов, «как на ПК», для тех, кому
  ступеньки не нужны;
- внутри 32 бита, вывод 48 / 96 кГц;
- рампа громкости (нет щелчков на нотах), панорама на канал, 16-битные сэмплы, 8–32 канала;
- по желанию — «Paula clean»: BLEP без фильтров A500 (ярко, как A1200, но без образов пересчёта).

## 8. С чего начать (макет, когда придёт PCM5102A)

1. Тестовая прошивка на RP макета: синус 1 кГц в I2S (`doc/zx-trinity.md`, п.15 — распиновка GP14..16).
2. **pocketmod** (MIT, один файл, без зависимостей) — разбор MOD и команды ProTracker; его микшер
   (без интерполяции, `increment = CCK / (период × Fвых)`) заменить на **Paula из pt2-clone**
   (`pt2_paula.c` + `pt2_blep.c` + `pt2_rcfilters.c`, BSD-3, ~660 строк): BLEP и фильтры A500 / A1200 / LED.
3. MOD с SD / из флеша → I2S, сравнение на слух с pt2-clone на ПК. **Замер — счётчиком тактов ядра
   `DWT_CYCCNT` (Cortex-M33)**: до и после расчёта каждого буфера; раз в секунду — по USB в терминал (потом —
   пакетом INFO в `#C1`): **максимум тактов на буфер**, средняя загрузка ядра в %, сколько голосов играло.
   По максимуму и тактам на голос — сколько каналов влезает с запасом. Пики разбирать — ножкой (GP17) на анализатор.
4. Потом — команды GS (загрузка модуля / сэмплов, плей) поверх того же микшера.

**Лицензии:** pt2-clone — BSD-3 (брать можно, с указанием автора), pocketmod — MIT; WinUAE, MilkyTracker,
PicoGUS — GPL (только как справочник, код не копируем — иначе вся прошивка под GPL);
`amiga_replacement_project` — CC BY-NC (только справочник).

## 9. Архитектура — решено (пользователь, 2026-10-18)

| Вопрос | Решение | Что из этого следует |
|---|---|---|
| Кто играет модуль | **только RP** | Спектрум заливает модуль (или берёт с SD Trinity) и командует: играть / стоп / позиция / громкость. Режима «регистров Paula» для плеера на Z80 нет. Разбор форматов — на RP |
| Каналов | **16–32** (до 32, как GUS) | микшер на 32 голоса; на 48 кГц в худшем случае (BLEP на каждом отсчёте) ~50 % ядра во float — поэтому микшер в фиксированной точке Q15 с DSP-командами (`SMLAD`), BLEP — только в режимах Paula; в Classic / HiFi — без него |
| Сэмплы | **8 и 16 бит** | формат сэмпла в описании голоса; 16 бит — HiFi, XM / S3M; PSRAM 8 МБ хватает |
| Частота вывода | **48 кГц** | BLEP Paula годится (≥ 31.4 кГц), I2S 48 кГц на PCM5102A |

**Порядок (пользователь, 2026-10-18): сначала Paula — 4 канала и MOD-плеер, точный звук; потом
совместимость с NeoGS и 8 каналов, дальше — больше каналов, если понадобится.** Микшер сразу закладываем
расширяемым (число голосов — параметр), но первый этап — ровно Amiga.

Форматы модулей на RP: сначала **MOD** (pocketmod, MIT); 32 канала нужны для **XM / S3M / IT** — их плеер
выбрать отдельно (по лицензии: не GPL). Режим звучания (Classic / Paula A500 / A1200 / HiFi) — на весь
вывод, переключается на лету.

## Выводы коротко

1. Звук Amiga = своя частота у каждого канала + ступеньки без интерполяции + 8 бит + ШИМ-громкость +
   RC 4.4 кГц (A500) / LED 3.1 кГц.
2. Точно повторяется программно: BLEP (minBLEP 16 × 16) + модели фильтров по номиналам — метод pt2-clone /
   WinUAE / MilkyTracker.
3. RP2350 тянет это за ~7 % ядра на 4 канала; внешний DSP и аналоговые фильтры не нужны.
4. Наружу — только PCM5102A. Режимы (Classic / A500 / A1200 / HiFi) — переключаются программно.
5. Первый шаг — pocketmod + Paula из pt2-clone на RP макета с PCM5102A.
