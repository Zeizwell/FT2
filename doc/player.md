# Плеер FT2 — проект (на согласование)

Пункт 5 плана. Плеер — плагин: свой код в своей странице, своя логика тиков и
скорости. Трекер только командует (играй / стоп) и читает его переменные.

## 1. Где и когда

- **Страница плеера** — своя, код с `#4000` (окно 1), как у тулз.
- **IM1, первым делом** (до мыши и вывода): коре ставит страницу плеера в окно 1,
  зовёт `Tick`, возвращает окно 1. Тулза в окне 1 при этом не мешает: IM1 сохраняет
  страницу и восстанавливает её.
- **Данные — в окна 2/3 на время тика:**
  - страница паттерна текущей позиции;
  - страница инструментов и орнаментов (`doc/instruments.md`, одна на трек).
  
  Ставит сам плеер, перед выходом возвращает как было.
- **Вывод в AY — в начале тика,** значения, посчитанные в прошлом тике. Тогда регистры
  пишутся в одну и ту же точку кадра, без дрожания. Затем счёт следующего.

## 2. Точки входа (таблица с `#4000`)

| Адрес | Что |
|---|---|
| `#4000` | `Init` — подготовить трек: страница трека в `SV_PLAY_SONG`, таблицы нот / громкости |
| `#4003` | `Tick` — каждый кадр из IM1 |
| `#4006` | `Mute` — заглушить AY (оба чипа) |

Команды из основного цикла — не вызовом, а переменной `SV_PLAY_CMD`. IM1 сам ничего
не решает. Плеер в начале `Tick` берёт команду и обнуляет её:

| Команда | Что |
|---|---|
| `PC_SONG` | сонг с позиции `SV_PLAY_POS` (F5, F6 с 0) |
| `PC_PATTERN` | паттерн позиции по кругу с роу `SV_PLAY_ROW` (F7, F8 с 0) |
| `PC_STOP` | стоп и тишина (Esc) |
| `PC_CONTINUE` | продолжить с того места, где остановились |

## 3. Переменные плеера (пишет только плеер, читают все)

| Переменная | Что |
|---|---|
| `SV_PLAY_STATE` | стоп / сонг / паттерн |
| `SV_PLAY_POS`, `SV_PLAY_ROW` | что сейчас играет (по ним едет полотно паттерна) |
| `SV_PLAY_TICK` | тик внутри роу |
| `SV_PLAY_SPEED` | текущая скорость (тиков на роу) — меняется командами |
| `SV_PLAY_LOOPED` | счётчик проходов (конец сонга, цикл паттерна) |
| `SV_PLAY_CH` | состояние каналов для экрана (6 × 8 байт): нота, инструмент, орнамент, громкость на выходе, тон / шум / огибающая вкл, период |
| `SV_PLAY_AY` | регистры AY, которые уйдут в чип (2 × 14) — для индикаторов и осциллографа |

Скорости, тики, позицию и роу ведёт сам плеер — ты так и сказал. Трекер своего
счётчика не держит: вместо нынешней имитации `Play_Step` полотно просто
показывает `SV_PLAY_POS` / `SV_PLAY_ROW`.

## 4. Тик

1. Команда → состояние (п.2).
2. Вывод в AY значений прошлого тика (TurboSound: чип 0, потом чип 1).
3. `SV_PLAY_TICK--`. Если 0 — следующая роу:
   - роу паттерна страницы текущей позиции (L 0..111, формат `sdk/plugin.asm`);
   - в конце паттерна — следующая позиция по ордеру (сонг) или роу 0 (паттерн);
   - нота / инструмент / орнамент / огибающая / громкость / команды в состояние канала;
   - `SV_PLAY_TICK = SV_PLAY_SPEED`.
4. Каждый канал: строка инструмента и строка орнамента (с накоплениями и циклом), слайды
   и команды → тон, шум, огибающая, громкость → `SV_PLAY_AY`.
5. Переменные для экрана.

## 5. Время

Худший случай — 6 каналов, 2 чипа, в каждом новая нота и команды. Цель — не больше
~15К тактов. Плеер FTC укладывает 3 канала в ~4–6К.

Мерить будем полосой времени (Ctrl+T), у плеера будет свой цвет.

## 6. Вопросы

1. Команды паттерна — 2 × 2 байта на канал. Какие делаем первыми? FTC: 1xx/2xx
   глисс, 3xx портаменто, 4xx шум, 500 ретриггер, Fxx скорость. Bitphase: A, V,
   1, 2, P, 4–8, D, S.
2. Таблицы нот: классика (ST) и 1.75 МГц, как в FTC — номер в заголовке трека?
3. Таблица громкости — `(i*j+7) div 15`, как в PT3 3.5+ и FTC?
4. «Огибающая нотой» в плеере: период огибающей = период тона / соотношение. Чья это
   настройка — инструмента или трека?
