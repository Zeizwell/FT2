# API карты ZX Trinity — стандарт

Одно место для всех: прошивки RP, Unreal, SDK, FT2. Новая фича = новая строка в таблицах ниже, сам стандарт не
меняется. Почему так решили — `doc/zx-trinity.md` п.14а (состояния), 14в (сервисы), 14г (слоты / задания).
Статус строк: **есть** — работает (протокол v2, RP-AY v17), **план** — номер закреплён, кода нет.

## 1. Транспорт (RP-AY)

Регистры AY, которых нет у чипа, — через `#FFFD` (выбор) / `#BFFD` (данные), как обычный AY.
**Есть ли карта — один раз при старте, пакетом `INFO`** (ответ `"TRIN"` + версия); дальше `#C0` читается только как статус.

| Рег | Запись | Чтение | Статус |
|---|---|---|---|
| `#C0` | ключ `"TRIN"` (4 записи подряд) — открыть поток; `0` — закрыть; любая запись — начать разбор заново | **байт статуса** (раздел 3), в любой момент; сейчас — `'T'` | план (сейчас `'T'`) |
| `#C1` | поток пакетов (раздел 2) | ответ на последний пакет с ответом | есть |
| `#C2..#CF` | запас | | |

Запись — `OUT (C),A` при постоянном `BC = #BFFD` (не `OTIR` / `INIR`: `B` — и счётчик, и адрес). Выбор TurboSound
(`#FF` / `#FE` в `#FFFD`) — как обычно, у каждого чипа свой поток. Сеанс: выбрать `#C0`, ключ -> выбрать `#C1` ->
пакеты подряд -> выбрать `#C0`, `0`. Подробно про номера регистров AY у других карт — `doc/ay-ports-map.md`.

## 2. Пакеты

Код `< #80` — **реалтайм** (плеер, каждый кадр): длина фиксирована, ответа нет. Код `≥ #80` — **служебные**:
`[код][длина 2 байта][данные]`, ответ — из `#C1`: `[длина 2 байта][данные]`. Неизвестный код — карта пропускает.

| Код | Имя | Данные | Ответ | Статус |
|---|---|---|---|---|
| `1` | `ROW` | канал 0..2, строка FX 14 байт (`doc/fx-row.md`), форма, фаза, флаг свипа — всего 19 байт с кодом | — | есть |
| `2` | `TABLE` | номер таблицы, 16 значений | — | есть |
| `3` | `RESET` | маска каналов (новая нота) | — | есть |
| `4` | `INFO` | — | `"TRIN"`, версия протокола (сейчас 2) | есть |
| `#80` | `SLOT_NEW` | тип (4 знака), размер (4), флаги (бит 0 — постоянный) | номер слота / 0 — нет места | план |
| `#81` | `SLOT_WRITE` | слот, смещение (4), байты | — | план |
| `#82` | `SLOT_READ` | слот, смещение (4), сколько (2) | байты | план |
| `#83` | `SLOT_INFO` | слот | тип, размер, флаги | план |
| `#84` | `SLOT_FREE` | слот | — | план |
| `#85` | `SLOT_LIST` | — | номера занятых слотов | план |
| `#90` | `SVC_LIST` | — | сервисы: номер, версия, имя 16 знаков, тип входа, тип выхода | план |
| `#91` | `SVC_CALL` | сервис, команда, слот входа, слот выхода, параметры | — (дальше — `JOB_*`) | план |
| `#A0` | `JOB_STATUS` | — | статус задания, прогресс 0..100 | план |
| `#A1` | `JOB_LOG` | — | текст лога задания | план |
| `#A2` | `JOB_STOP` | — | — | план |
| `#B0` | `CFG_GET` | тег (4 знака) | значение | план |
| `#B1` | `CFG_SET` | тег, значение | — | план |
| `#B2` | `CFG_SAVE` | — (записать конфиг во флеш) | — | план |
| `#C0` | `MODE` | состояние: `AY` (стоп самоплеера) | — | план |

## 3. Состояние и байт статуса (чтение `#C0`)

| Биты | Что | Значения |
|---|---|---|
| 1..0 | состояние чипа | 0 `AY` (по умолчанию: команды Спектрума + FX), 1 `PLAY` (самоплеер), 2 `UPDATE`, 3 `TEST` |
| 3..2 | задание | 0 нет, 1 идёт, 2 готово, 3 ошибка |
| 4 | FX включены | |
| 5 | ошибка карты (код — в `INFO`) | тест чипа не прошёл, конфиг побит, откат прошивки |
| 7..6 | запас | 0 |

Переходы: `AY -> PLAY` — `SVC_CALL` плеера («играть»); `PLAY -> AY` — `STOP`, `MODE AY`, сброс; `UPDATE` / `TEST` —
только из `AY`. Сброс — всё в `AY`, тишина. В `PLAY` записи Спектрума в AY до чипа не доходят (тень и чтение работают).
**Инициализация любого плеера через SDK шлёт `MODE AY`.** Задание — не состояние: идёт в `AY` и `PLAY`.
Программа: `SVC_CALL` -> опрос статуса (показывать прогресс) -> «готово» / «ошибка» — сама решает, что дальше.

## 4. Слоты

Слот — контейнер данных на карте: номер 1..254 (0 — нет), тип, размер, временный (ОЗУ, пропадает при сбросе) или
постоянный (флеш RP; SD — у RP-GS). **Слот 255 — конфиг этой RP** (постоянный, всегда есть).

| Тип | Что | Статус |
|---|---|---|
| `CFG ` | конфиг RP: блоки тег + длина + версия, две копии + CRC | план |
| `FT2C` | трек FT2 (`doc/formats/ft2.md`) | план |
| `BTP ` | проект Bitphase (`doc/formats/btp.md`) | план |
| `MYM ` | maxYMiser (`doc/formats/mym.md`) | план |
| `SNDH`, `YM  `, `PSG ` | музыка для самоплеера | план |
| `PRST` | пресеты карты (todo п.63) | план |
| `FW  ` | образ прошивки | план |

## 5. Сервисы

Сервис — блок прошивки: номер, версия, имя, тип входа, тип выхода, команды. Регистрация — строка в таблице
сервисов RP. AY-сервисы — в RP-AY, GS-сервисы — в RP-GS.

| № | Сервис | RP | Вход -> выход | Команды | Статус |
|---|---|---|---|---|---|
| 1 | плеер | AY | `SNDH` / `YM` / `PSG` -> играет | `PLAY`, `STOP`, `PAUSE` | план |
| 2 | конвертер | AY | `BTP` / `MYM` / MOD -> `FT2C` + лог | `RUN` | план |
| 3 | обновление | AY / GS | `FW` -> прошивка | `RUN` | план |
| 4 | тест карты | AY | — -> лог | `RUN` | план |

## 6. SDK (Z80) — `sdk/trinity_ay.asm`

| Вызов | Вход | Выход | Статус |
|---|---|---|---|
| `Ayfx_Info` | HL — буфер | `"TRIN"`, версия | есть |
| `Card_Detect` | — | есть ли карта (`INFO`: `"TRIN"`), версия | план (сейчас `Ayfx_Detect` — по `'T'`) |
| `Card_Status` | — | байт статуса (чтение `#C0`) | план |
| `Slot_New` / `Slot_Write` / `Slot_Read` / `Slot_Free` / `Slot_List` | как пакеты `#80..#85` | | план |
| `Svc_List` / `Svc_Call` | как `#90` / `#91` | | план |
| `Job_Status` / `Job_Log` / `Job_Stop` | | | план |
| `Cfg_Get` / `Cfg_Set` / `Cfg_Save` | тег, значение | | план |
| `Play_File` | файл | `Slot_New` + `Slot_Write` + `Svc_Call` плеера | план |
| `Player_Init` | — | `MODE AY` | план |

Плееры FT2 и игр шлют реалтайм-пакеты (`ROW` / `TABLE` / `RESET`) напрямую — так быстрее (`srs/player.asm`, `Fx_*`).
