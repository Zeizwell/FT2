# ZX Trinity — звуковая карта для ZX Spectrum

**Trinity** — три звука в одной карте: Спектрум (AY / TurboSound), Atari (эффекты
громкостью поверх AY: SID, цифродрамы, тремоло) и Amiga (GS со звуком Paula и лучше).

Статус: концепт, схемы нет. Здесь — что решили и почему.

---

## 1. Что умеет

- 2 × настоящих AY-8910 / YM2149 (TurboSound) — звук живой, не эмуляция.
- Эффекты Atari-типа поверх AY (таймерные, как у Bitphase): SID — RP управляет **выходами** каналов;
  Syncbuzzer, FM, Env FM — **RP пишет в регистры AY сама** (R13, период тона, R11/R12) с частотой таймера
  (решено 2026-10-11: закладываем все эффекты сразу; RP встаёт на запись в AY наравне с шиной).
  Регистры — `doc/ay-ports-map.md`, п.5а.
- General Sound — нативный и совместимый, режимы Classic / Paula A500 / Paula A1200 / HiFi.
- AY и GS одновременно.
- Два выхода: **на наушники** (с усилителем) и **линейный** (отдельный, без усилителя).
- Общая громкость + балансы AY и GS; **внешний USB-регулятор** (крутилка, как на клавиатурах).

Режимы: чистые 2×AY; 2×AY + эффекты; GS; AY + GS.

## 2. Принципы

- **Доступность для всех**: дёшево, детали есть на LCSC / JLC и на Али, плату можно
  собрать дома руками или заказать собранной.
- Живой характер AY («ламповость») сохраняем: эффекты — пассивным делителем на выходе,
  сигнал AY ничем активным не окрашивается.
- Две RP с самого начала: AY-часть и GS-часть не смешиваем в одном процессоре.
- Звуковой тракт — главное место, где выигрываем у других (см. п.6).
- Всё открытое: схема и плата в KiCad, прошивки, файлы для заказа.

## 3. Архитектура

```
 ZX-BUS / NemoBus
   │
   ├─ буферы 5 В <-> 3.3 В (74LVC245 и т.п.)
   │
   ├─ 2 × AY (DIP-40 в панельках) ──► выходы 6 каналов ──► AY-тракт (п.4) ──┐
   │        ▲ запись регистров (живые AY на шине)                            │
   │        │                                                                │
   ├─ RP-AY: снифает запись в регистры AY, знает периоды, громкость,        │
   │         огибающую; крутит потенциометры по SPI; ловит фронты каналов    │
   │         (компараторы -> PIO)                                            │
   │                                                                         ▼
   └─ RP-GS: интерфейс GS на шине (порты #B3/#BB), движок GS,          аналоговый
             PSRAM под сэмплы, I2S -> PCM5102A ──────────────────────► сумматор
                                                                           │
                                     громкость: vol_gs (в GS), master ◄───┘ 
                                                                           │
                                                          усилитель на наушники, линия
```

- RP — готовыми модулями (Raspberry Pi Pico / RP2040-Zero / RP2350): без пайки QFN,
  прошивка перетаскиванием файла по USB (UF2). Голые чипы — вариант для сборки на заводе.
- RP-GS — RP2350 (ему нужны производительность и PSRAM).

### Две RP — кто что делает

Обе — **Pico 2** (RP2350, ~5 $): RP-GS нужна PSRAM; RP-AY — три блока PIO (шина, USB, PS/2,
фронты); одинаковые модули проще закупать и прошивать. Связь между ними не нужна: громкость и
эффекты — на RP-AY, звук GS — на RP-GS, сводятся в аналоге.

| | RP-AY | RP-GS |
|---|---|---|
| задачи | снифает запись в оба AY; потенциометры (эффекты 6 каналов + master наушников); фронты каналов (компараторы); USB host (клава, мышь, крутилка, геймпад); PS/2 на Evo; эффекты от трекера FT2 | интерфейс GS на шине (`#B3` / `#BB`); движок GS + эмуляция Z80; PSRAM 8 МБ; I2S -> PCM5102A; SounDrive / Covox |
| ножки (у Pico 2 26 GPIO) | шину не слушает целиком — только сами AY: данные 8 + BDIR, BC1 = 10; SPI 4; фронты 6; USB 2; PS/2 4 — **26, впритык** | данные 8, адрес 8, управление ~4, I2S 3, CS PSRAM 1 — **~24** |

Точная распиновка — на этапе схемы; не влезет — модуль на RP2350B (48 GPIO), дороже.

У автора едет плата **RP2350B + 16 МБ флеш + 8 МБ PSRAM** -> её под **RP-GS и макет**:
1. модуль PCM5102A (Али ~2 $) по I2S;
2. макет без Спектрума: RP2350B + PCM5102A + наушники — отладка движка (Classic / Paula / HiFi,
   щелчки, кросс-фид);
3. потом шина через буферы — совместимость с GS.
RP-AY — потом обычная Pico 2.

## 4. AY-часть: эффекты через выходы

Идея как на Atari (SID, цифродрамы), но процессор Спектрума и сам AY ничего не делают:
внешнее устройство меняет уровень каждого из 6 каналов.

### Решение: цифровые потенциометры MCP4351

| | |
|---|---|
| микросхема | MCP4351 (Microchip): 4 потенциометра, 257 положений, SPI до 10 МГц |
| сколько | 2 шт. = 8 каналов: 6 — каналы AY, 2 — master наушников (стерео, после сумматора) |
| номинал | 10 кОм |
| корпус, питание | TSSOP-20, 5 В |
| цена | ~1 $ за шт. (сверить на LCSC / Али перед заказом) |
| скорость | ~1.6 мкс на запись: десятки тысяч изменений уровня в секунду |

Рассматривали и отвергли:
- AD5206 (6 каналов) — подходит, но дороже, на Али много копий;
- PT2258, M62429 (звуковые регуляторы, лог. шкала) — I2C / медленно, эффекты не потянут;
- PGA2311 — звук отличный, но ~5 $ и двуполярное питание;
- аналоговые ключи для вкл/выкл — не нужны: громкость 0 на потенциометре = выключено.

### Тракт канала

```
выход AY ─► родная нагрузка AY ─► ОУ-повторитель ─► потенциометр (A - сигнал,
                                                     B - земля, W - выход) ─► ОУ-повторитель ─► сумматор
```

- Родная нагрузка — как на обычной TS-плате: AY звучит привычно.
- Потенциометр — пассивный делитель, в верхнем положении почти прозрачен (~50 Ом движка):
  без эффектов AY звучит как есть.
- Шкала линейная — логарифм громкости таблицей в RP.

### Эффекты

| Уровнем канала | Записью в AY (RP пишет сама, решено 2026-10-11) |
|---|---|
| SID: меандр громкостью, скважность, её модуляция | syncbuzzer (перезапуск огибающей R13) |
| тремоло, гейт, ADSR и затухание поверх AY | FM, детюн (смена периода) |
| цифродрамы: канал AY в постоянном уровне, потенциометр играет сэмпл | |

Без щелчков: менять уровень, пока меандр канала в нуле. Для этого фронты каналов
ловятся компаратором на канал -> PIO RP-AY. Для эффектов, где щелчок и есть звук (SID),
синхронизация не обязательна.

Связь с трекером FT2: это FX-объекты формата (SID, буззер, таймерные FX из Bitphase,
`doc/instruments.md`). Плеер пишет параметры FX в порты карты, RP-AY исполняет их сам.

## 5. GS-часть

### Как звучат другие (разобрано по схемам в `schemes/`)

**NeoGS (rev C-VS)**: Z80 20 МГц, ПЛИС EP1K30, 2 МБ SRAM, MP3 — VS1033.
4 канала сводятся цифрой в ПЛИС (8 бит × 6 бит громкости) -> **TDA1543** (16 бит,
без передискретизации и цифрового фильтра, ~90 дБ) -> **NE5532**. MP3 подмешан в аналоге.
Звук «тёплый» (зеркальные частоты не срезаны), шум и разрядность — уровня 90-х.

**ZX-MultiSound**: GS-ЦАП — 1-битная сигма-дельта прямо в ПЛИС (32 МГц, 1-й порядок,
7 бит модуля + знак, «середина» — тактовый сигнал), громкость — долей времени, опора —
питание выводов ПЛИС -> RC-фильтр -> MCP602 (КМОП-ОУ общего назначения).
Дёшево, но цифровой шум ПЛИС идёт в звук, разрешения мало.

**Оригинальный GS**: 4 × 8-битных ЦАП с аналоговой громкостью, сведение в аналоге.

### Почему Amiga (Paula) звучит «сочно»

1. Каждый канал играет со **своей** частотой (по периоду ноты), без пересчёта —
   ступеньки сэмпла звучат музыкально. У GS программа Z80 пересчитывает все каналы
   к одной частоте — отсюда алиасинг и шипение на высоких нотах.
2. 8 бит на канал, ступенька без интерполяции.
3. Громкость 6 бит — ШИМ (~55 кГц), не умножение.
4. Аналоговые фильтры: A500 — постоянный RC ~4.4 кГц + «LED» ~3.1 кГц 2-го порядка;
   A1200 — постоянный ~30+ кГц + тот же «LED». (Частоты — сверить по pt2-clone, 8bitbubsy.)

### Решение: режимы звучания

| Режим | Что делает |
|---|---|
| Classic | как оригинальный GS: ступеньки на частоте вывода |
| Paula A500 / A1200 | канал по своему периоду, ступеньки с ограничением полосы (BLEP, как в pt2-clone), модели фильтров A500 / A1200 и «LED» |
| HiFi | полифазная интерполяция, внутри 24–32 бита, плавная громкость без щелчков, 48 / 96 кГц |

Переключаются на лету.

### Вариант А (основной) — цифровой

RP2350 считает каналы и фильтры -> I2S -> **PCM5102A** (~2 $, ~112 дБ).

### Вариант Б (опция) — «железная» Paula

4 × 8-битных R-2R ЦАП, каждый со своей скоростью (PIO + DMA), честная ШИМ-громкость,
настоящие RC и «LED»-фильтры на ОУ. R-2R питать через защёлки 74HC574 от чистого
аналогового питания (не с ножек RP — иначе беда MultiSound), резисторы — сборки 0.1%.

### Совместимость

- **Нативный движок** — команды GS (загрузка модуля, плей, сэмплы) исполняет наш микшер:
  отсюда качество и режимы Paula / HiFi.
- **Эмуляция Z80 GS** — для софта, который грузит в GS свой код. RP2350 тянет Z80
  12–24 МГц с запасом. Записи в ЦАП перехватываем с отметкой времени.

### Возможности сверх

- PSRAM 8 МБ (APS6404, ~1 $) — сэмплов больше, чем у NeoGS.
- 8 каналов, 16-битные сэмплы, панорама на канал.
- MP3 / OGG программно на RP2350, без отдельного декодера.
- По желанию: реверберация, хорус.

### RP и память GS

- **RP2350** (не RP2040): 150 МГц, 2 × Cortex-M33 с FPU / DSP, 520 КБ SRAM — микшер 8+ каналов
  с интерполяцией, фильтры Paula, эмуляция Z80 GS.
- **PSRAM 8 МБ** (APS6404, SOP-8, ~1 $) на QSPI (второй CS) — у RP2040 так нельзя. Больше,
  чем у всех (GS 512 КБ–1 МБ, NeoGS до 2–4 МБ).
- Сборка: Pico 2 (~5 $) + PSRAM-чип на нашей плате (рекомендуется, дёшево) или модуль
  с PSRAM (Pimoroni Pico Plus 2, ~10 $).

### SD-карта

- **Решено (2026-10-12): одна microSD на RP-GS.**
  - **Автообновление прошивок:** в начале флешки каждой RP - загрузчик. При включении RP-GS смотрит на SD файл
    новой прошивки (например, `TRINITY/RPGS.BIN`, `TRINITY/RPAY.BIN`): версия новее - шьёт себя, а RP-AY - по SWD
    (2 провода, как Picoprobe) или по UART через её загрузчик; файл переименовать в `.OLD`, чтобы не шиться по кругу.
    Страховка - родной USB BOOTSEL (UF2) у обеих RP. Другие пути заливки: со Спектрума через окно 0, по USB.
  - **Потом - чтение с карты для Спектрума:** файлы (модули, сэмплы, MP3) с SD карты через её порты или окно 0 -
    для машин без своей SD, автономного проигрывания, совместимости с NeoGS; наш FAT32-драйвер берёт носитель
    таблицей порта (init / read512 / write512 / sync).
  - **Доступ — шлюз секторов, как у NeoGS** (разобрано 2026-10-12 по
    `pentevo/soft/WC/source/core32/drivers/SD_NGS.ASM`, BUDDER/MGN 2015): карта на SPI самого NeoGS; Спектрум
    заливает в GS программу (1К в `#4000`, команды GS «загрузить память» `#14` и «перейти» `#13`), дальше через
    порты GS `#BB` (команда / статус) и `#B3` (данные): `#20` — инициализация, `#10` — читать сектора (номер
    4 байта + сколько, по 512 байт), `#12` — писать. FAT ведёт Спектрум. У Trinity шлюз сразу в прошивке RP
    (регистры карты, например `#BA` — команда / статус, `#BB` — данные; на плате — через окно 0). Можно
    повторить команды NeoGS — тогда подойдут старые драйверы WC.
  - **На Еве WC и TS-BIOS такую SD не видят:** в последней WC драйвер SD(NGS) убран, носители — по нумерации
    TS-BIOS. FT2 видит своим FAT32-драйвером (модуль порта, от TS-BIOS не зависит). Для системы — **форк WC**
    (исходники — `pentevo/soft/WC/source`) с драйвером SD Trinity. Пользователь потом хочет убрать на Еве IDE
    (сейчас там HDD) и поставить на его место VDAC — тогда носители: своя SD Евы (Z-Controller, основная) и SD на
    карте Trinity — вторая, вместо HDD (второй SD на самой Еве нет: CS SD2 есть только на внутренней SPI, с шины не
    попасть).
- Для GS не нужна: модули и сэмплы Спектрум грузит через порты GS.
- Посадочное место microSD (~0.1 $) — **по умолчанию не запаивать**, поддержка позже:
  для Спектрумов без своей SD, автономного MP3, совместимости с NeoGS.
- В TS-Config / Evo SD своя (Z-Controller `#57`/`#77`). SD на NeoGS там не используется:
  в последней WC драйвер SD(NGS) убран (`pentevo/soft/WC/exe/WC_History.txt`, стр. 8:
  «убран SD(NGS) драйвер, порядок носителей приведен к нумерации из ts-bios»). Наш FAT32-драйвер
  FT2 может взять другой носитель своей таблицей порта (init / read512 / write512 / sync).

### Шина

Чтение портов GS (`#B3` / `#BB`) — ответ внутри цикла IORQ. На 3.5 МГц PIO успевает,
на турбо (7 / 14 МГц) — WAIT или защёлка, заранее держащая состояние порта.

### Обмен данными без портов (маппинг памяти) — разобрано 2026-10-11

Желание автора: гнать данные между картой и компом не портами, а окном памяти.

- **Как у NeoGS (демо The Link, Alone Coder 2009; разбор: github.com/alfishe/TheLink-Pentagon1024-NeoGS,
  `docs/tutorial/01-the-machine.md`, п.1.5):** режим ZX-DMA карты. Карта (`DMA_MOD`=1 `#1B`, адрес
  `#1C`-`#1E`, пуск — бит 7 `CST` `#1F`) подменяет ПЗУ: каждое чтение Спектрума из `#0000`-`#3FFF`
  даёт следующий байт памяти карты (адрес растёт сам), запись — в память карты; не готов байт — `/WAIT`.
  Чтение отдаёт байт ПРЕДЫДУЩЕГО чтения (первый — мусор). Кадр: `LD D,(HL) : LD E,(HL) : PUSH DE`.
  Держится на сигнале шины, которым карта отключает родное ПЗУ (`/ROMCS`, Пентагон).
- **Evo — МОЖНО, через ПЗУ в окне 0 (схема rev C + Verilog, разобрано 2026-10-11; скрины —
  `schemes/zxevo_revc/rom_cpu_fpga.webp`, `zxbus_fpga_pins.webp`):**
  - ПЛИС: `csrom` (нога 150, `zmem.v`: `csrom = rom_n_ram`) → инвертор D14:3 → сеть `CSROM` (шина, **A25**)
    → **R56 680 Ом** → сеть `RDROM` = `/CE` флешки 29F040 (D3, нога 22) и шина **A15 `CSROMCE`**.
  - Данные флешки — прямо на шине данных Z80; когда окно 0 читает ПЗУ, ПЛИС шину не держит
    (`zd_ena = !rom_n_ram && memrd`). `/OE`, `/WE` флешки — от ПЛИС (`ROMOE`, `ROMWE`).
  - Карта: видит обращение к ПЗУ по `CSROM` (A25), тянет `CSROMCE` (A15) вверх (перебивает 680 Ом —
    флешка гаснет) и сама отдаёт байт на D0..D7 при `/MREQ`+`/RD`, ловит запись при `/WR`. Ровно так
    ZXNetUSB rev C выдаёт `ZBLKROM` на A15 (`schemes/zxinet/cpld_zxbus.png`). На шине есть `/WAIT` (B21).
  - Ограничения: только окно 0 (`#0000`-`#3FFF`) и только пока в нём ПЗУ (не ОЗУ, не vDOS); на 14 МГц
    карта должна успеть в цикл чтения (CPLD успевает; иначе `/WAIT`). Кэш TS-Config ПЗУ не касается
    (кэшируется только ОЗУ: `ramreq` при `!rom_n_ram`) — проверить на железе.
  - Клоны Evo (rev CS, CU2 и др., схемы на GitHub) по словам автора совместимы — разводку A15 / A25
    проверить, если карта пойдёт на них.
- **Решено (2026-10-11): обмен через окно 0 — на плате карты (этап 2), не на переходнике.** Режим —
  **поток, адрес не важен** (как NeoGS): каждое чтение отдаёт следующий байт (RP готовит его
  заранее — успевает на 14 МГц без `/WAIT`), каждая запись кладёт следующий; адресные линии карте
  не нужны (D0..D7, `/MREQ`, `/RD`, `/WR`, `CSROM`, выход на `CSROMCE`). Начальный адрес / режим —
  портом карты перед обменом. Применения: **запись** — заливка прошивки RP (загрузчик в ОЗУ RP
  шьёт её флешку; страховка — родной USB BOOTSEL), **чтение** — данные и картинки от RP (например,
  осциллограф: RP-AY видит все записи в AY).
  - Z80: `pop` — два цикла чтения = 2 байта (первый — младший регистр), 5 тактов на байт;
    пачкой `pop` в регистры -> SP в ОЗУ -> `push` — ~10–11 тактов на байт; `ldir` — ~21.
    DMA TS-Config окно карты не видит (ходит по страницам ОЗУ) — только процессор.
  - На время обмена: `di` (прерывание сделало бы `push` в карту), в окне 0 — ПЗУ, стек и код —
    в окнах 1–3 (у FT2 в окне 0 коре: IM1 `#0038`, стек `#3E00`).
  - Цена картинки: 6 окон 96×32 по 4 бита = 9К за кадр ≈ 92К тактов (треть кадра на 14 МГц);
    по 1 биту на точку — 1.1К, ~12К тактов, в 4 бита разворачивает Спектрум.
- **Что есть у Evo вместо — DMA TS-Config с внешними устройствами** (`common/dma.v`):
  `DMA_IDE_RAM` / `DMA_RAM_IDE` — карта на разъёме IDE, 16-битные слова, без процессора (~2.2 такта
  на байт); `DMA_SPI_RAM` / `DMA_RAM_SPI` — через SPI (свой CS на `#77`), медленнее. Самое простое —
  порты ZX-BUS и `INIR` / `OTIR` (~21 такт на байт, процессором).
- **ZXNetUSB (NedoPC, W5300 + SL811):** в эмуляции ZXMAK2 (`aaydev/ZXMAK2-Fork`,
  `ZxNetUsbDevice.cs`) у CPLD ревизии C есть два взаимоисключающих окна — портов и **памяти** (биты 4
  и 2 порта `#82AB`), но эмулировано и используется драйвером NedoOS только окно портов: `#81AB`
  адрес, `#82AB` управление, `#83AB` прерывания, W5300 — порты `#xxAB` (A15=0, A8..A13 — адрес).
  Окно памяти на Evo — через `ZBLKROM` → A15 `CSROMCE` (схема rev C, `schemes/zxinet/`), см. выше.

## 6. Звуковой тракт — где выигрываем

Главный враг не ЦАП, а цифровой шум шины Спектрума и общая с ним земля.

- Питание звука: LC-фильтр от 5 В шины + малошумящий LDO.
- Звёздная земля, аналог отдельно от цифры, ЦАП — у выхода.
- Сведение AY и GS — аналоговый сумматор; `vol_gs` до него (цифрой в GS), master — после
  (иначе общая громкость не управляет AY).
- **Выход на наушники** — свой усилитель: TPA6132A2 (~0.5–1 $, без разделительных
  конденсаторов, выход «от земли», хорошо качает наушники) или ОУ с повторителем по току.
- **Линейный выход** — отдельный, от сумматора через свой буфер, без усилителя наушников:
  одно не грузит другое. Уровень **фиксированный**: master и USB-крутилка регулируют
  **только наушники** (решение автора). Баланс `vol_gs` — до сумматора, на оба выхода.
- **Громкость — просто** (решение автора: «громко — взял убавил», AY не трогать, на звук не
  влиять, RP не грузить):
  - AY не трогаем: потенциометры каналов — только для эффектов, без эффектов на максимуме;
  - баланс — одна величина `vol_gs`: громкость GS цифрой в RP-GS, AY стоит как есть;
  - общая громкость — одна (master наушников), см. ниже. Пассивный делитель, на звук не влияет;
    поворот крутилки — 1–2 записи по SPI, RP не грузит.
- **Master наушников** — 2 свободных канала второй MCP4351 (левый / правый) после сумматора.
  Нуля-перехода у потенциометра нет: при повороте возможен «зиппер» на малой громкости —
  RP шагает по 1 ступени по лог. таблице.
- **Внешний USB-регулятор громкости** — отдельная крутилка, как на клавиатурах
  (на Али ~3–5 $, обычное USB HID: громче / тише / mute). RP читает её как USB host.
  Родной USB RP оставить под прошивку (UF2), крутилку — на отдельные ножки через PIO-USB
  (Pico-PIO-USB): без конфликта прошивки и крутилки. На карте — разъём USB-A.

| | NeoGS | MultiSound | Trinity |
|---|---|---|---|
| ЦАП GS | TDA1543, ~90 дБ | 1 бит в ПЛИС | PCM5102A, ~112 дБ |
| Сведение | цифра, 14–16 бит | доля времени | цифра, 24–32 бита |
| Частота каналов | пересчёт программой Z80 | то же | своя у каждого (Paula) или интерполяция (HiFi) |
| Режимы звука | один | один | Classic / Paula A500 / A1200 / HiFi |
| Эффекты AY | — | — | SID, цифродрамы, тремоло — выходами AY |

Доказательство: одни и те же MOD и синусы с выхода каждой карты через нормальную
звуковую карту -> шум, искажения, спектр (RMAA или аналог) + слепое прослушивание.

## 6а. USB-клавиатура, мышь, крутилка -> PS/2 (как HIDman)

Клавиатуру через ZX-BUS полноценно не сделать: Спектрум читает её портом `#FE` (полуряды по
старшим линиям адреса, ответ D0–D4); подмена ответа (IORQGE) отключает родную клавиатуру и
бит EAR, подтяжка линий данных поверх ULA на клонах ненадёжна. Поэтому — как в переходниках
с PS/2 выходов Evo:

```
USB-клавиатура ─┐                        ┌─► PS/2 клавиатура ─► Evo X11, ближнее гнездо
USB-мышь ───────┼─► RP (USB host) ─► PS/2 ┤
USB-крутилка ───┘                        └─► PS/2 мышь ──────► Evo X11, дальнее гнездо
```

- ZX Evo rev C: **X11** — сдвоенный PS/2, ближнее к плате гнездо — клавиатура, дальнее — мышь
  (`pentevo/docs/revC/zxevo_user_manual.pdf`, п. 3.11). У автора — Evo rev C.
- Работает родным путём Evo: контроллер PS/2, лог клавиатуры TS-Config (на нём трекер FT2),
  Kempston mouse Evo. Без перехвата портов и конфликтов на шине.
- Электрика: PS/2 — открытый коллектор, подтяжка 5 В со стороны Evo; RP 3.3 В — через BSS138
  на линию (4 линии) или 74LVC07. На карте — 2 × mini-DIN 6 или гребёнка + кабель до X11.
- USB host — на **RP-AY** (лёгкая нагрузка), PIO-USB: 2 порта USB-A (клавиатура, мышь),
  крутилка — третьим портом или через простой хаб.
- Для машин без PS/2: мышь можно отдавать по шине как Kempston mouse (`#FBDF` X, `#FFDF` Y,
  `#FADF` кнопки / колесо) — на Evo отключать (там своя на тех же портах).
- USB-геймпад -> Kempston джойстик (`#1F`) — по шине, тоже на USB host.

### Допы: что ставим

| Что | Решение |
|---|---|
| AY | 2 × панелька DIP-40 под YM2149 / AY-3-8910 (совместимы по ножкам; у YM2149 ещё SEL) |
| Wi-Fi (ZiFi) | **не ставим** (решено): у Evo свой, родным путём (ESP32 по SPI Evo или ZiFi по UART Evo). На Еве — модуль [ZiFi-ESP32-S3-Zero](https://github.com/andrewinsidelazarev/ZiFi-ESP32-S3-Zero) в слот ZiFi (UART 115200, двоичный протокол ZiFi, HTTP/HTTPS, FTP, SMB, OTA, плагины WC); Gerber переходника в репозитории есть — **заказать вместе с платой Trinity** (отдельным проектом в той же корзине JLC). Под другие машины Wi-Fi не делаем: софт (FT2) — только под TS-Config (решение пользователя). Исключение — маленькая служебная программка для работы с картой (RP) на Пентагоне 128К + TR-DOS, и всё |

| USB-клава, мышь, крутилка | RP -> PS/2 на разъём X11 Evo (п. 6а) |

Вторая SD в TS-Config — второй CS на внутренней SPI Evo (порт `#77`: D1 — SD, D2 — FT812,
D3 — SD2, D4 — ESP32; данные `#57`; `pentevo/fpga/current/z80/zports.v`), с ZX-BUS туда
не попасть: SD на карте — отдельное устройство на своих портах.

## 6б. Аудиотракт: чек-лист (чтобы GS был «в 100 раз круче»)

1. **Питание аналога ±5 В** (LM2664 / ICL7660 ~0.2 $ + LC-фильтр): AY однополярный (0…~1 В),
   PCM5102A — вокруг нуля (2.1 В действ.); на одном 5 В пришлось бы «виртуальной землёй» и
   конденсаторами — хуже по шуму и запасу. ±12 В — только если на шине есть +12 (не на всех машинах).
   Цифра — 5 В шины через LC + малошумящий LDO для 3.3 В ЦАП.
2. **Такт I2S без дрожания**: системная частота RP с целым делением — например 153.6 МГц ->
   BCK 3.072 МГц (48 кГц × 64), делитель 50. Дробное деление в PIO = jitter = муть на верхах.
3. **Без щелчков**: XSMT PCM5102A держит RP до готовности; ступенька постоянки AY при включении —
   глушить на старте; GS-сэмплы беззнаковые (середина 128): остановка канала и смена громкости —
   плавно (ramp).
4. **Без перегруза**: запас по уровню при сведении 4–8 каналов GS + AY, мягкий ограничитель в цифре.
5. **Стерео для наушников**: кросс-фид (подмес каналов, настраиваемый, как в эмуляторах Amiga) —
   только на выход наушников; AY — ABC / ACB / моно.
6. **Разводка**: аналоговая земля отдельно, связь с цифровой в одной точке у ЦАП; RP, SPI и шина —
   подальше от аналога; питание USB-устройств — отдельно от звука.
7. **Выходы**: линейный — буфер + ~100 Ом последовательно + разделительный конденсатор; наушники —
   TPA6132A2 или ОУ с повторителем; защита разъёмов от статики.

Что делает GS лучше всех: режимы Paula A500 / A1200 / HiFi; каждый канал со своей частотой
без зеркальных частот (BLEP); без щелчков; чистый тракт (~112 дБ, ровный такт, своё питание);
кросс-фид; мягкий ограничитель; по желанию — лёгкая реверберация (выключаемая).

## 7. Доступность и цена

- RP — модулями на штырях; AY — в панельках (дефицит, карта от них не зависит);
- двухслойная плата до 100×100 мм (самый дешёвый тариф JLC);
- детали — из базового списка JLC / LCSC и с Али.

Прикидка без AY: 2 модуля RP 4–8 $, потенциометры ~2 $, ОУ ~1 $, PCM5102A ~2 $,
буферы шины ~1 $, PSRAM ~1 $, усилитель / разъёмы / мелочь — несколько $.
Итого ~15–20 $ + плата.

## 8. Решено / открыто

Решено:
- FM — нет; Wi-Fi — нет; MIDI — нет; SAA1099 — нет; «железная» Paula (R-2R) — отбой (программно лучше).
- Сборка — **дома руками**: RP модулями (Pico / Pico 2), корпуса DIP / SOIC / TSSOP, без QFN.
- GS — **только совместимость** (свой трекер под GS не пишем).
- Эффекты RP-AY задаёт **трекер FT2** — регистры карты придумываем вместе с трекером.

Порядок и планы:
- **Сначала AY, потом GS.** Сначала макетка, потом схема и плата.
- **Этап 1 (сейчас, 2026-10-11): переходник на 2 × AY-3-8910 через DIP-40** — без RP и без маппинга.
  Ставим **настоящие AY-3-8910 (DIP-40)**, не YM2149F и не YM2203. AY-3-8912 — DIP-28, другая
  распиновка, не подходит. На Али под видом AY-3-8910 часто перемаркированные YM2149 — проверять:
  ножку 26 на землю — YM2149 (SEL) делит такт на 2, звук на октаву ниже, у AY-3-8910 она тестовая,
  ничего не меняет; ещё у YM2149 огибающая 32 шага (на медленной пиле плавнее). На плате ножку 26 не
  подключать: у YM2149 внутренняя подтяжка (без делителя), у AY — ни на что не влияет; встанет любой.
- **Этап 2: плата карты** — RP, буферы 74LVC245, обмен через окно 0 (поток, см. «Обмен данными без
  портов»).
- Макет AY: 2 панельки YM2149, выборка AY с шины, RP-AY смотрит данные AY и BDIR/BC1,
  2 × MCP4351 + ОУ + компараторы на выходах каналов. Такт AY 1.75 МГц — на карте (делитель от
  такта шины или генерирует RP) — решить на схеме.
- Макет GS (второй): плата RP2350B 16 МБ + 8 МБ, PCM5102A; можно на макетке с разъёмом ZX-BUS
  (распиновка — `pentevo/docs/revC/zxevo_user_manual.pdf`, п. 5). Проверка: звук без шины ->
  порты `#B3` / `#BB` на 3.5 МГц -> на 7 / 14 МГц (успевает ли, нужен ли WAIT).
- **5 В**: RP2040 — не терпит нигде; RP2350 — большинство GPIO терпят 5 В на входе, только при
  поданном питании, ножки АЦП (RP2350B: GPIO40–47) — нет. Правило: всё к шине и к AY — через
  буферы 74LVC245 / 74LVC244; АЦП-ножки к 5 В не подключать.
- Инструмент схемы и платы (EasyEDA или KiCad) — после макета; возможно, разводят и заказывают
  знакомые железячники. Я: схема, цепи, номиналы, расчёты, проверка; трассировку руками в
  редакторе не делаю, но даю правила и проверяю готовую плату. KiCad удобнее для совместной работы
  (текстовые файлы в git), EasyEDA — проще и детали LCSC сразу.

- **Эмуляция Тринити в Unreal** (`unreal/`, наша сборка v142): множитель уровня на каждый канал AY
  («потенциометр») + логика RP-AY (SID, тремоло, гейт, цифродрамы) по портам карты; GS в Unreal
  уже есть (Z80 + ПЗУ = режим совместимости), Paula / HiFi — в его сведение; SounDrive есть.
  Условие — сначала **регистры карты** (одна спецификация для эмулятора, железа и FT2). Правка
  Unreal — по правилу CLAUDE.md (новая сборка рядом, своё имя и ini, по одной правке).
- **Xpeccy** — автор поддержит сам (автор карты с ним на связи). Ему — отдельный документ для
  авторов эмуляторов: регистры карты и что каждый эффект делает со звуком, с цифрами (частоты,
  шаги уровня, порядок обновления). Готовить вместе с регистрами.

## 9. Требования и предпочтения автора (не терять)

- Проект и плата — **очень доступные для всех**: детали по ~1 $, «валом» на Али и др.,
  удобно разводить, просто управлять.
- Схема — **простая**. Лишнего (аналоговых ключей и т.п.) не ставить, если то же делает
  уже стоящая деталь (громкость 0 на потенциометре = канал выключен).
- **Ламповость AY сохранить**: AY живой, эффекты не должны окрашивать звук.
- **В AY не писать**: не грузить AY (выставлять порт, писать регистры) ради эффектов —
  только управлять его выходами снаружи. Эффекты как на Atari, но чаще.
- GS — **лучший из всех** по звуку и возможностям; цель — уровень Amiga Paula или выше.
- Сравнивать с тем, что есть у автора: ZX-MultiSound (стоит у него), NeoGS и др.
- Название — **ZX Trinity**: Спектрум + Atari + Amiga.
- Выходы: **наушники с усилителем + обычный линейный**; **внешняя USB-крутилка громкости**
  (отдельное устройство, как регулятор на клавиатурах).

## 10. Исходный концепт (как его сформулировал автор, до обсуждения)

- Карта для ZX-BUS / NemoBus: 2 × AY-8910 (TurboSound) + аппаратное улучшение AY через
  внешние ЦАПы + нативный GS высокого качества + AY и GS одновременно + выход на
  наушники с общей громкостью.
- **RP-AY**: настоящие AY на шине, RP снифает запись в регистры, знает периоды,
  огибающие, шум; через внешние ЦАПы управляет амплитудой каждого из 6 каналов;
  **quasi-synchronous** модуляция относительно периода канала (обновление ~period / 16),
  каналы обновляются независимо, **лёгкий рассинхрон специально допускается**
  («чтобы звук дышал»); дополнительные управляющие регистры (расширенные порты)
  включают режимы FX.
- **RP-GS**: полный интерфейс ZX-BUS, нативный GS-движок (без эмуляции Z80), приём
  сигнала от RP-AY, финальный микшер AY + GS, master volume + балансы, выход + усилитель.
- GS: режимы Classic (совместимость), Paula (zero-order hold + period-based), HiFi
  (16 бит, качественный ресемплинг, повышенная частота, «14-bit трюк»); 4 или 8 каналов.
- Громкость (исходно): master + `vol_ay` / `vol_gs`; внешняя USB-крутилка (HID Volume), возможно
  на отдельной маленькой микросхеме.

Что изменилось после обсуждения:
- «внешние ЦАПы» -> цифровые потенциометры MCP4351 на выходах AY (п.4);
- «без эмуляции Z80» -> нативный движок **плюс** эмуляция Z80 для совместимости (п.5);
- USB-крутилку RP читает сам, отдельная микросхема не нужна (п.6);
- сведение AY + GS — аналоговое, master — после сумматора (п.6).

## 11. Технические заметки (чтобы не выводить заново)

- **Фаза меандра AY** из регистров не видна (только период и громкость) -> для записи
  уровня «в паузу» нужны компараторы на выходах каналов -> PIO. Иначе
  quasi-synchronous превращается в случайный рассинхрон.
- **AD5206** — это не ЦАП, а 6-канальный цифровой потенциометр (256 положений, SPI,
  11 бит на запись: 3 адрес + 8 данных). Подходит по смыслу, отвергнут по цене / копиям.
- **Обычный SPI-ЦАП** (DAC8568, AD5628 и т.п.) сигнал AY через себя не пропускает —
  для регулировки уровня нужен потенциометр, умножающий ЦАП (AD5449 / AD5429) или VCA
  (THAT2180). Умножающий ЦАП / VCA — дороже и сложнее, для эффектов Atari не нужны.
- **Потенциометр в верхнем положении**: 255/256 у AD5206 (у MCP4351 — 256/256 есть),
  сопротивление движка ~50 Ом. Шкала линейная: ~48 дБ на 8 битах -> лог. таблица в RP.
- **Нагрузка AY**: оставить родную (~1 кОм на землю как на TS-плате), потенциометр
  отделить повторителем, выход потенциометра — тоже через повторитель (высокое Rвых).
- **Шина 5 В / RP 3.3 В** — буферы с управлением направлением.
- **Порты GS** `#B3` / `#BB`: ответ в цикле IORQ; турбо 7 / 14 МГц — WAIT или защёлка.
- **GS-софт, грузящий свой Z80-код** — без эмуляции Z80 не работает (причина эмуляции).
- **Источник шума №1** в картах — цифра шины и общая земля, а не ЦАП.

## 14. Похожий проект: VDAC4 (Andrew Lazarev) — 2026-10-12

https://github.com/andrewinsidelazarev/VDAC4 (MIT). «Графический сопроцессор + HDMI-конвертер для ZX Evolution /
TS-Config + сетевая карта + звуковой модуль». Плата «A4» на разъёме IDE-40 Евы; софт Wi-Fi ESP32 для SPI на IDE40 —
уже в отдельном репозитории (со слов пользователя).
- **Связь:** ESP32-S3-Zero (N8R8) — ведомый SPI Slave HD на **шине SD-карты Евы** (порты `#57` / `#77`), линии SCK /
  MOSI / CS выведены на IDE (35 / 33 / 1) через D12 74HCT245, на плате понижены 74LVC245 (ESP GPIO12 / 11 / 10 = FSPI).
  MISO — ESP GPIO13 или Tang (FPGA79) через 1G97, поднят TXU0101 (включает NAND) на IDE 27 (вход ПЛИС, R20 1к к +5).
- **Протокол:** Z80 ведущий — пишет запрос в общий буфер ESP и перечитывает до ответа; **большие блоки — DMA TS-Config
  в режиме SPI** (то, чего нет у портов ZXBUS). Кадры ZiFi (`Docs/PROTOCOL.md`).
- **ESP:** Wi-Fi, TCP / HTTP(S), FTP, SMB, NTP, OTA по сети (`update_vdac4.sna`), мост VFS к SD Евы (окна до 16К),
  USB-флешки, модули ELF с карты (PSRAM), плагины WC; звук I2S -> PCM5102: MP3 (Helix), MOD / S3M / XM (libxm,
  загрузчики TS-Labs). Эмуляция в Unreal: `TS_ZIFI32=VDAC4`.
- **Tang (Gowin)** — графический сопроцессор / HDMI (подробностей в репо пока нет, `Docs/VDAC4.md` не выложен).

Для нас:
- Пересекается с Тринити (сеть, звук PCM, SD-шлюз, OTA) и с Revolution (внешний 2D / HDMI на Gowin).
- **Идея для обмена Тринити на Еве:** SPI SD-шины + DMA TS-Config — потоковый обмен без процессора, уже работает у
  них. Медленнее (SPI ≤ 14 МГц), но без `/WAIT` и окна 0. Сравнить с нашим протоколом «2 регистра + поток».
- Есть смысл связаться с автором: общий протокол / кадры вместо двух несовместимых.
- **Своя прошивка TS-Config** у VDAC4 (со слов пользователя) — нужен свой bitstream на Еве. Плата и её софт не
  работают на штатной Еве -> раскол. **Тринити не должна требовать своей прошивки TS-Config** — только штатное железо
  Евы (ZXBUS / порты), всё новое — на стороне карты. Форки прошивок сейчас обычное дело — допустимо как **ускорение**
  (например, DMA порт <-> память): с форком быстрее, без него всё работает. Добавки — только новое, под ключом.
  Лучше один общий форк с фишками всех плат (включаются ключами), чем у каждой платы свой.
- **VDAC4 — требования автора (из чата, 2026-10-12):** модуль Waveshare ESP32-S3-Zero **N8R8**; на Еве **замкнут J1
  (Reset IDE)** — по ноге 1 IDE идёт CS ESP; **прошивка TS-Config с SPI 28 МГц**. В нашей копии `pentevo/fpga/current`
  SCK = fclk / 2 = **14 МГц** (`common/spi.v`: `sck = counter[0]`, счётчик на `fclk` 28 МГц) — значит, у них более
  новая / изменённая сборка. Сборка VDAC2 + ESP уже есть в исходниках: `quartus_vdac2/tune.v`, ключи `IDE_VDAC2` +
  `ESP32_SPI` («VDAC3»): SCK `ide_a[0]` (IDE 35), MOSI `ide_a[1]` (33), CS FT812 `ide_rd_n`, CS ESP `ide_rs_n` (IDE 1),
  MISO общий `ide_rdy` (27), `esp_ft_spi_dis` — Ева отпускает SPI, ESP говорит с FT812 сам. VDAC2 и ESP — вместе,
  нельзя только IDE-винт (те же ноги).
- **Сетевые модули ZiFi — варианты (Andrew Lazarev, чат 2026-10-12):**
  - ESP-01 (512К флеш), прошивка AT 1.1 / 1.2 — `zifi.spg`, FTP-сервер с пассивным приёмом до 256К;
  - ESP-01S (1М), свой C++ — `zifi.spg`, NTP, FTP с активным приёмом, WebDAV;
  - ESP32-S3-Zero N4R2 — `zifi.spg`, NTP, FTP (активный), SMB-сервер, скринсейвер погоды (обычный и под VDAC2),
    обновление прошивки и WC;
  - ESP32-S3-Zero **N8R8** — то же + **музыкальный плеер**: MIDI (SF2), MOD, IT, XM, OPL2–4, SAA, AY-TSFM, MP3, FLAC,
    WAV (чипы — программной эмуляцией на ESP, звук в I2S);
  - ESP32-S3 N16R8 («Highlander») — VFS: FTP, vtrd.in, музыка, видео.
  Зоопарк вариантов; звук — плеер файлов, не звуковая карта для софта (своё API, не GS / не TS-FM).
- **Tang Nano 20K VDAC — структура платы** (картинка из чата, A3.1 / PCB A3.1-P6, 58 × 75 мм, 4 слоя, 16.09.2026;
  «аппаратные испытания не подтверждены»). Плата на TS-PORT40 (IDE) Евы, сборка VDAC2:
  - видео Евы **RGB555 + PAL (16 бит)** -> 2 × 74LVC257 (16 -> 8 линий, две фазы, `MUX_SEL` от Tang, 5 -> 3.3 В) ->
    Tang Nano 20K (GW2AR-18): приём, обработка, **HDMI** штатным разъёмом Tang;
  - управление: 74LVC245 (PCLK, HS/VS, M_SEL, SCK, MOSI, CS_FT_n, CS_ESP_n) -> Tang и ESP; SPI Евы — одна шина, два CS;
  - **Tang отвечает на CS FT812** (`MISO_FT`, `FT_INT_n`) — судя по меткам, изображает графический чип VDAC2;
  - ESP32-S3-Zero N8R8: SPI slave для Евы, **QSPI master к Tang** (полудуплекс, IRQ_n Tang -> ESP), I2S -> GY-PCM5102 ->
    R17 / R18 27к -> AUDIO IN Евы (звук ESP идёт в микшер Евы);
  - возврат: MISO_FT / MISO_ESP -> U6 (выбор) / U7 (разрешение, от двух CS) -> U8 TXU0101 -> IDE 27;
    FT_INT_n -> U11 TXU0101 + R19 1к (разрешение от M_SEL) -> IDE 15.
  Для Revolution: готовый пример «Ева + внешняя Gowin по SPI / QSPI» (HDMI, сопроцессор). Полоса — SPI Евы
  (≤ 28 МГц, ~3.5 МБ/с), не шина памяти.
